## TAB 1: STORE INFORMATION

### Fields Admins Can Edit:
- Store Name (e.g., "GlowNatura")
- Email (e.g., "hello@glownatura.com")
- Phone (e.g., "+234 123 456 7890")
- Address (e.g., "123 Beauty Street")
- City (e.g., "Lagos")
- State (e.g., "Lagos State")
- Postal Code (e.g., "100001")
- Country (e.g., "Nigeria")

### Where This Information Appears:
1. **PDF Receipts/Invoices** (auto-generated by backend)
   - Company header section
   - Footer contact info

2. **Email Templates**
   - Footer of all order emails
   - Contact information section

3. **Frontend Website**
   - Contact page
   - Footer
   - About page

### API Endpoint:
```
PUT /api/settings
Body: { store: { name, email, phone, address, city, state, postalCode, country } }
```

## TAB 2: WHATSAPP SETTINGS

### Fields Admins Can Edit:
- **Enabled** (Toggle: Yes/No)
  - Controls if WhatsApp button shows on frontend
  
- **WhatsApp Number** (Text field)
  - Must include country code (e.g., "+2348012345678")
  - This is the number customers will contact
  
- **Default Message** (Text area)
  - Pre-filled message when customer clicks WhatsApp button
  - Example: "Hi, I'm interested in your skincare products"

### Where This Information Appears:
1. **Frontend Website**
   - Floating WhatsApp button (usually bottom-right corner)
   - When clicked, opens WhatsApp with pre-filled message

2. **Product Pages**
   - "Contact Us on WhatsApp" button

### What Admins CANNOT Edit:
- Button position (controlled by frontend code)
- Button design/color (controlled by frontend code)
- Button icon (controlled by frontend code)

### How It Works:
1. Admin enables WhatsApp and sets number + message
2. Frontend checks if enabled via API
3. If enabled, frontend shows WhatsApp button
4. When clicked, opens: `https://wa.me/2348012345678?text=Hi,%20I'm%20interested...`

### API Endpoint:
```
PUT /api/settings
Body: { whatsapp: { enabled: true, number: "+234...", message: "Hi..." } }
```

## TAB 3: EMAIL TEMPLATES

### Templates Admins Can Edit:

1. **Order Created (Payment Pending)**
   - Sent when: Customer places order
   - Variables: {customerName}, {orderId}, {total}, {items}

2. **Payment Confirmed**
   - Sent when: Admin confirms payment
   - Variables: {customerName}, {orderId}, {paidAmount}, {paymentMethod}
   - Includes: PDF receipt attachment

3. **Order Shipped - Local Delivery**
   - Sent when: Admin updates status to "shipped" with local delivery
   - Variables: {customerName}, {orderId}, {estimatedDelivery}

4. **Order Shipped - Courier**
   - Sent when: Admin updates status to "shipped" with courier
   - Variables: {customerName}, {orderId}, {trackingNumber}, {trackingUrl}

5. **Order Shipped - Pickup**
   - Sent when: Admin updates status to "shipped" with pickup
   - Variables: {customerName}, {orderId}, {pickupLocation}

6. **Order Delivered**
   - Sent when: Admin updates status to "delivered"
   - Variables: {customerName}, {orderId}, {deliveredAt}

7. **Order Cancelled**
   - Sent when: Admin cancels order
   - Variables: {customerName}, {orderId}, {cancelReason}, {refundAmount}

### What Admins Can Edit for Each Template:
- Subject line
- HTML content (rich text editor)
- Plain text version (for email clients that don't support HTML)
- Active/Inactive status (enable/disable sending)

### What Admins CANNOT Edit:
- Variable names (these are hardcoded in backend)
- Email sending logic (when emails are triggered)
- PDF receipt generation (template is coded)

### Available Variables:
- `{customerName}` - Customer's full name
- `{customerEmail}` - Customer's email
- `{orderId}` - Order ID (e.g., ORD-1234567890)
- `{orderDate}` - Order creation date
- `{total}` - Order total amount
- `{subtotal}` - Subtotal
- `{shippingFee}` - Shipping fee
- `{items}` - List of items (formatted)
- `{paymentMethod}` - Payment method
- `{trackingNumber}` - Shipping tracking number
- `{trackingUrl}` - Full tracking URL
- `{storeName}` - From store settings
- `{storeEmail}` - From store settings
- `{storePhone}` - From store settings

### API Endpoints:
```
GET /api/email-templates              # Get all templates
GET /api/email-templates/:type        # Get specific template
PUT /api/email-templates/:id          # Update template
POST /api/email-templates/:id/preview # Preview with sample data
POST /api/email-templates/:id/test    # Send test email
PUT /api/email-templates/:id/restore  # Restore to default
```

## IMPORTANT CLARIFICATIONS

### What Settings DOES Control:
- Store information shown on receipts and emails
- WhatsApp button visibility, number, and message
- Email template content and variables
- Social media links in footer and emails

### What Settings DOES NOT Control:
- PDF receipt design/layout (coded in backend)
- WhatsApp button position/styling on frontend (coded in frontend)
- Email sending triggers (coded in backend)
- Frontend page layouts (coded in frontend)
- Product prices, stock, etc. (that's in Products module)
- Order processing (that's in Orders module)

## BACKEND INTEGRATION

### Settings Model (MongoDB):
```javascript
{
  _id: ObjectId,
  store: {
    name: String,
    email: String,
    phone: String,
    address: String,
    city: String,
    state: String,
    postalCode: String,
    country: String
  },
  whatsapp: {
    enabled: Boolean,
    number: String,
    message: String
  },
  social: {
    facebook: String,
    instagram: String,
    twitter: String,
    tiktok: String
  },
  updatedAt: Date
}
```

### How Backend Uses Settings:

1. **PDF Receipt Generation** (`src/utils/pdfGenerator.js`):
   - Fetches store info from Settings
   - Adds to PDF header and footer

2. **Email Sending** (`src/utils/emailService.js`):
   - Fetches email templates from EmailTemplate model
   - Fetches store info from Settings
   - Replaces variables with actual data
   - Sends email

3. **Frontend API** (`GET /api/settings`):
   - Frontend fetches settings on load
   - Shows/hides WhatsApp button based on enabled status
   - Uses social links in footer

## USER FLOW EXAMPLE

### Scenario: Admin Updates WhatsApp Number

1. Admin logs into admin panel
2. Navigates to Settings page
3. Clicks "WhatsApp" tab
4. Sees current settings:
   - Enabled: Yes
   - Number: +2348012345678
   - Message: "Hi, I'm interested in your products"
5. Updates number to: +2348098765432
6. Updates message to: "Hello! I'd like to learn more about GlowNatura"
7. Clicks "Save"
8. Admin panel calls: `PUT /api/settings` with new data
9. Backend updates MongoDB Settings document
10. Success toast shows: "WhatsApp settings updated"
11. Frontend website now uses new number for WhatsApp button

### What Happens on Frontend:
1. User visits GlowNatura website
2. Frontend calls: `GET /api/settings`
3. Sees `whatsapp.enabled = true`
4. Shows floating WhatsApp button (bottom-right)
5. User clicks button
6. Opens: `https://wa.me/2348098765432?text=Hello!%20I'd%20like%20to%20learn%20more...`
